# Database

PostgreSQL 16, schema managed **only** by Flyway (`backend/src/main/resources/db/migration`). Hibernate runs with
`ddl-auto: validate`, so a mismatch between entities and migrations fails at startup. Migrations run automatically on
every start (local, CI tests, Render).

- `V1__init_schema.sql` — all tables, constraints, indexes, `order_number_seq`
- `V2__reference_cuisines.sql` — cuisine catalogue (reference data, not demo data)

Add a new `V3__…sql` for every change; never edit an applied migration.

## Tables

| Table | Notes |
|-------|-------|
| `users` | role `CUSTOMER/COOK/ADMIN`, status, bcrypt `password_hash`, unique `lower(email)` |
| `cook` | 1:1 with user; story (`bio`, `headline`), `approval_status`, denormalised `rating` + `review_count` |
| `kitchen` | 1:1 with cook; address, lat/lng, `verification_status`; `kitchen_photo` holds photo URLs |
| `cook_document` | FSSAI / ID / other, status, expiry |
| `cuisine`, `cook_cuisine` | many-to-many |
| `dish` | price ≥ 0, category enum, `active` flag (soft delete) |
| `batch`, `batch_dish` | capacity > 0, `reserved_quantity ≤ capacity`, cut-off, pickup/delivery windows, batch price per dish |
| `cart`, `cart_item` | one cart per customer; unique `(cart, dish, batch)` |
| `orders`, `order_item` | `order_number` from a sequence (`GS10001…`); item name + price snapshotted |
| `payment` | one row per gateway interaction (charge/refund) |
| `delivery_order` | provider booking, tracking URL, quoted/actual cost |
| `review` | ratings 1–5, unique `(order_id, customer_id)` |
| `favorite_cook` | PK `(customer_id, cook_id)` |
| `notification` | in-app notifications |

All primary keys are UUIDs generated by the application. Money is `NUMERIC(10,2)`. Timestamps are `timestamptz`.
Status columns are strings with `CHECK` constraints that mirror the Java enums.

## Constraints worth knowing

- `price >= 0`, `quantity > 0`, `capacity > 0`, ratings `BETWEEN 1 AND 5`
- `CHECK (reserved_quantity <= capacity)` on `batch`
- unique `(order_id, customer_id)` on `review`; PK `(customer_id, cook_id)` on `favorite_cook`

## Indexes

`cook(locality)`, `cook(approval_status)`, `dish(cook_id)`, `batch(available_date)`, `batch(status)`, `batch(cook_id)`,
`orders(customer_id)`, `orders(cook_id)`, `orders(order_status)`, `review(cook_id)`, plus FK helper indexes.

## Seed data

`DemoDataSeeder` (Java, so passwords are hashed properly) runs when `gharse.seed.enabled=true`. It is idempotent
(skips when `admin@gharse.demo` exists). To reset locally: `docker compose down -v && docker compose up -d postgres`.
